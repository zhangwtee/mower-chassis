# 规格：底盘状态机


## 一、要解决什么

能不能动由几个条件共同决定：使能开关、电压、急停、自检结果、指令是否最新。

用一堆独立标志分别表示这些条件，容易出现"互相盖掉"和"漏判"，某条判定被更靠后的
一条覆盖掉，或者某条压根没人读。所以这里收成**一个状态变量**，每个状态明确写清
允许什么、禁止什么。

## 二、状态

| 状态 | 含义 |
|---|---|
| `INIT` | 上电静默期，10 秒内不响应任何下行帧 |
| `IDLE` | 已使能，没有速度指令 |
| `RUN` | 已使能，按指令闭环运行 |
| `SELFTEST` | 自检脚本控制电机，忽略外部指令 |
| `ESTOP` | 急停锁存，运动与刀片全部禁止，等 CMD=8 |
| `FAULT` | 自检失败锁存，需复位 |

`ESTOP` 和 `FAULT` 本身就是锁存，不再另设标志位。

## 三、转移

| 从 | 到 | 条件 |
|---|---|---|
| `INIT` | `SELFTEST` | 上电计时到 10 s，且 `SELFTEST_ON_BOOT` 打开 |
| `INIT` | `IDLE` | 上电计时到 10 s，且 `SELFTEST_ON_BOOT` 关闭 |
| `IDLE` | `RUN` | 收到非零速度指令，且允许运动 |
| `RUN` | `IDLE` | 指令归零，或指令超时 |
| `IDLE` / `RUN` | `SELFTEST` | 收到 CMD=5（`IDLE` 时立即进，`RUN` 时先停车再进） |
| `SELFTEST` | `IDLE` | 自检脚本走完 |
| `SELFTEST` | `FAULT` | 自检任一检查项失败 |
| 任意 | `ESTOP` | 收到 CMD=7 |
| `ESTOP` | `IDLE` | 收到 CMD=8 **且** 物理急停开关已松开 |
| `FAULT` | — | 只能断电复位 |

物理急停开关（使能开关 `EN`）不锁存，按连续条件处理：开关在断开位就一直禁止运动。
硬件如果是自锁蘑菇头，那锁存由开关本身完成；固件不重复做，免得出现"软件认为已解除、
开关还在断开位"的矛盾。

## 三之一、自检

开机自动跑一次，之后靠 CMD=5 手动触发，两者共用同一套脚本。

| 步 | 动作 | 时长 | 通过条件 |
|---|---|---|---|
| 1 | 电机 0，读编码器静止 | 200 ms | 两轮计数接近 0 |
| 2 | Vx = +0.15 m/s | 600 ms | 两轮编码器均为正，量级 0.1~0.25 m/s |
| 3 | Vx = −0.15 m/s | 600 ms | 两轮均为负 |
| 4 | Vz = +0.4 rad/s | 600 ms | 左负右正 |
| 5 | 舵机 1500→500→1500→2500→1500 | 2 s | 无反馈，只动作不判定 |
| 6 | 停车、清 PI | 200 ms | — |

约 4.2 秒（420 拍）。自检期间刀片强制关闭，外部速度指令一律忽略。

三条判定上的约束，都是实测才会暴露的问题：

1. **第 2~4 步前 20 拍不计入判定。** 电机从 0 到 0.15 m/s 需要时间，加速段的采样
   会把最小值拉到接近 0，导致「正走」那一项必然判失败。这段叫 settle。
2. **自检受使能开关和欠压管。** 断开使能开关或电压低于 20 V，自检立即中止退回 `IDLE`，
不算通过也不算失败。开关一断就要中止自检，否则开关断着电机照样被驱动。
3. **从 `RUN` 触发自检要先停车。** 直接进自检的话，第一项「两轮计数接近 0」会因为车还在
   滑行而失败。所以 `RUN` 收到 CMD=5 先回 `IDLE`，等两轮实测速度都小于 0.05 m/s 才真正
   开始；期间如果又收到新的非零速度指令，就取消这次自检（操作者显然想开车）。
   等超过 2 秒还没停下也取消，不会卡在那里。

**第 5 步验证不了舵机**：继电器和舵机都没有回读，这一步只能确认"不卡死"，不能确认"到位"。

**开机自检会让车实际前后移动约 20 cm。** 必须在地面上、周围留空。`SELFTEST_ON_BOOT` 可以关掉这一段。

时间线：上电 → 静默 10 s → 自检 4.2 s → 可控制，**合计 14.2 秒**。上位机的开机等待应按 15 秒设。

## 四、允许运动的条件

`RUN` 状态内还要再判：

```
允许 = 电压 > 20.0 V  &&  使能开关闭合  &&  指令年龄 <= 500 ms
```

指令超时 500 ms 的取法：上位机桥的看门狗也是 0.5 s，两个数字对齐不会互相打架。
上位机 20 Hz 发帧，500 ms 相当于容许连丢 10 帧。

## 五、允许刀片的条件

```
刀片允许 = (状态 == IDLE 或 RUN) && 电压 > 20 V && 刀片命令年龄 <= 300 ms
```

刀片命令不是置位保持，是**周期刷新**：蓝牙 APP 按住不放或上位机反复下发，超时自动关。
这条是重写时新增的，之前一旦置位就一直转。

刀片在 `ESTOP`、`FAULT`、`SELFTEST`、`INIT` 一律禁止，且进入这些状态时立即关。

## 六、各状态的输出

| 状态 | 电机 | 刀片 | 舵机 |
|---|---|---|---|
| `INIT` | 0 | 关 | 中位 1500 |
| `IDLE` | 0 | 按第五节条件 | 跟随指令 |
| `RUN` | PI 输出 | 按第五节条件 | 跟随指令 |
| `SELFTEST` | 自检脚本直接给 | 关 | 自检脚本 |
| `ESTOP` | 0，解轴 | 关 | 保持不动 |
| `FAULT` | 0，解轴 | 关 | 保持不动 |

"解轴"指清 PI 积分并把 PWM 置 0，让轮子可自由推动；"锁轴"本次不用。

## 七、输入信号

| 信号 | 来源 | 更新频率 | 备注 |
|---|---|---|---|
| 电压 | ADC | 10 Hz | 已经过滑窗滤波 |
| 使能开关 | GPIO | 100 Hz | 连续条件，不锁存 |
| 速度 / 回充 / 对接指令 | 协议解析 | 20 Hz | 记录"最后一次收到的时间" |
| 急停 / 解除 | 协议解析 | 事件 | 置请求标志，状态机下一拍处理 |
| 自检触发 | 协议解析 | 事件 | 同上 |
| 刀片命令 | 协议解析 / APP | 事件 | 记录刷新时间 |
| 编码器 | 定时器 | 100 Hz | 两个轮子 |
| IMU | I2C | 100 Hz | 只用于停车判定和遥测 |

## 八、能在 PC 上测的部分

状态机写成 `chassis_step(&ctx, dt)` 形式的纯函数，输入是上面那张表里的值，
输出是状态和"允许位"。那么可以不碰硬件直接测：

- 状态转移表逐条走一遍
- 超时边界（499 ms 仍允许、501 ms 禁止）
- 锁存：进 `ESTOP` 后发速度帧不动，收到 CMD=8 才恢复
- 刀片刷新超时
- 电压跨阈值抖动

## 九、待定

指令超时和刀片超时的具体数值，现在是 500 ms / 300 ms，但是这是本车数据。
特别注意要用实际帧率实测，特别是上位机在弱网下会不会出现连续丢帧。
