# 架构

## 一、分成三层

```
app/    业务：控制环、安全判定、协议、遥测、自检        ← 会一直改
bsp/    板级：电机/编码器/串口/CAN/OLED/Flash/按键      ← 跟着硬件走
cmsis/ spl/ rtos/    第三方，不改
```

**app 只调 bsp 的接口，不碰寄存器；bsp 不知道业务，只提供读写**。
唯一例外是 `app/irq.c`，那是中断总入口。

还有一点**可以用纯逻辑写清楚的，就不要让它碰硬件**。
`protocol.c` 和 `telemetry.c` 只 include `stdint.h`。
这是下位机与上位机之间唯一的协议，也是最需要测试的部分。

## 二、任务划分

| 任务 | 频率 | 优先级 | 栈（字） | 职责 |
|---|---|---|---|---|
| `chassis` | 100 Hz | 4 | 待定 | 状态机、安全判定、逆解、PI、PWM、刀片、自检 |
| `imu` | 100 Hz | 3 | 待定 | 读 ICM20948，算零偏 |
| `telemetry` | 20 Hz | 2 | 待定 | 上行帧组包 + UART1/UART3/CAN 发送 |
| `hmi` | 10 Hz | 1 | 待定 | 电压采样、OLED、APP 显示、蜂鸣器、LED |

优先级数字在 `app/app.h` 的 `PRIO_*` 里，不在各模块自己定义。

**为什么 telemetry 比 chassis 低**：它每个周期要阻塞发 51 字节×2 路串口（约 8.9 ms / 50 ms）。
和控制在同一个优先级会把 100 Hz 环的抖动拉大。

**为什么刀片不单独开任务**：刀片是安全关键执行器，必须和"低压 / 急停 / 软停"在同一处判定。
独立任务只能靠共享变量间接同步，做不到"任一条件成立立刻关"。所以刀片状态机放在 `chassis` 里。

### 控制链路的四道处理

从收到速度指令到 PWM 输出，中间必须过四道，顺序不能换：

| 顺序 | 处理 | 参数 | 少了会怎样 |
|---|---|---|---|
| 1 | 限幅 | ±3.5 m/s | 异常指令直接给满 PWM |
| 2 | 平滑 | 每拍 0.02 m/s（2 m/s²） | 指令跳变 → PI 打满 → 轮子窜、打滑、电流冲击 |
| 3 | 逆解 | 轮距 0.435 m | — |
| 4 | PI | kp=ki=300，限幅 ±16800 | — |

前两道在 `app/speed_smooth.c`，后两道在 `kinematics.c` 和 `pi.c`。四道都是纯函数，都能 PC 测试。

**平滑只作用在目标速度上，不作用在 PWM 上。** 离开 `RUN`（急停、失能、超时）时直接
`motor_set(0,0)`，要的是立刻断电停车，不是优雅减速。

### 预留但当前没用的

- `pi_clear_output()`：驻车时把 PI 输出每次减 1 清残余。IDLE 改成闭环保持之后不需要了，
  留给将来做"平地自动释放"时用。现在没有调用者。

### IMU 的坐标是上位机的

`g_state.accel` / `g_state.gyro` 存的是**已经转成上位机坐标**的值：

```
ROS X = 传感器 Y
ROS Y = -传感器 X
ROS Z = 传感器 Z
```

旋转在 `imu_task` 里、把陀螺的静态偏移减掉之后做。串口遥测和以后任何读 `g_state` 的地方看到的是同一个
坐标，不用各自再转。

失能（`flag_stop == 1`）时遥测的 Z 轴角速度发 0，免得停着的车上位机看到在转。

### 舵机：需要上机确认行程

舵机由两处驱动：**自检扫描**（500 → 1500 → 2500 → 1500，先慢后快）和**协议下发的脉宽**。

自检扫描是**每拍 20 µs 的三角波**，全程 2 秒。不用几档跳变，是因为跳变会硬拽舵机；
平滑扫能看出有没有卡顿，对齿轮也更友好。

协议下发的脉宽按 500~2500 限幅。**实际行程
必须上机确认**——方向、能不能扫到头，这是需要实机确认的。

协议下发的舵机值仍然按 500~2500 限幅，但这个还是需要实机确认，因为这是本机的数据。

### 串口发送：整帧或整帧丢

`uart_write` 先把整帧的长度和 `ring_free()` 比一次：**放不下就整帧丢掉**，一个字节都不写。

缓冲装不下就整帧丢掉，不发半帧。上位机那边虽然有帧头重同步能吃掉残帧，但那是它的
容错，不该当成自己的机制用；而且半帧后面紧跟的整帧，会让它多扫一遍。

`ring_free()` 读的是生产者自己的 `head` 和消费者的 `tail`。SPSC 下 `tail` 只会单调前进，
万一读到旧值算出的空闲量偏小，也就是宁可多丢一帧，不会写穿。

### 事件标志的清除时机

`chassis_task` 的每拍顺序是固定的：

```
link_poll()  →  chassis_step()  →  link_clear_once()
```

先让状态机消费，再清除。几种边界都已经验证：

| 情况 | 结果 |
|---|---|
| 同一拍同时收到急停和解险 | `estop_req` 优先；ESTOP 分支要求 `!estop_req` 才解除 |
| 急停只发一次 | 标志清掉后 ESTOP 是锁存的，不会自己回 IDLE |
| 舵机只发一次 | `servo_valid` 清了但值保留，舵机不回中 |
| 卡顿跳拍 | 既不移 poll 也不 clear，标志留到下一拍，无害 |

### 诊断页

OLED 共三页，**长按用户按键切换**。

```
STK words
CH 412  TE 301
IM 250  HM 210
UP 123s
```

四个数是各任务的**栈历史最低剩余量**（单位：字 = 4 字节），每 100 圈采一次。栈深度没法
静态算准，只能跑了之后读这个数。`D` 是两路串口累计丢掉的整帧数，`B` 是两路解析器累计的坏帧数——
这两个数接在诊断页第三行。

分配与实际对照：

| 任务 | 分配 | 说明 |
|---|---|---|
| chassis | 512 字 | 控制环，调用链最深 |
| telemetry | 384 字 | 组帧 + 两路串口 + CAN |
| imu | 384 字 | I2C 读写 |
| hmi | 384 字 | OLED + 声光 |

**任何一个剩不到分配量的四分之一，就该把它的栈加大。** 这是上机清单里的一项影响要求。

`uxTaskGetStackHighWaterMark` 需要 `INCLUDE_uxTaskGetStackHighWaterMark = 1`，已开。

第三页是**安全链**，专门用来现场验指令丢失保护：

```
SAFETY
AGE 120 ms
U 24.1  EN 1
FS 0
```

`AGE` 是当前指令距上一条有效指令过了多少毫秒（ms）。上位机停发之后它会一路涨，涨到 500 时车停——这个数是
**能直接看见保护在生效**的，比看状态从 RUN 变 IDLE 更早、更明确。
翻页逻辑抽成了 `diag_page_next_of()` 放在头文件里，PC 测试能直接覆盖。

### 两道指令丢失保护

这道保护和上位机那道**各管一段**，不是重复：
**各管一段**，不是重复：

| 层 | 位置 | 阈值 | 管什么 |
|---|---|---|---|
| 固件 | `safety_move_ok()` 判 `cmd_age` | 500 ms | 收不到下行帧就退回 `IDLE` |
| 上位机 | 桥的 `cmd_vel` 看门狗 | 500 ms | nav 侧停发就补一帧零速 |
| 上位机 | 桥的 ACK 超时 | 1.5 s / 0.6 s | 发出去的指令迟迟看不到效果就报 |

三者覆盖的故障不同：

| 故障 | 靠哪一道 |
|---|---|
| nav 节点崩了，桥还活着 | 上位机 `cmd_vel` 看门狗（固件看不见） |
| 桥崩了，串口线还在 | 固件 500 ms 超时 |
| 串口线断了 / 板子重启了 | 固件 500 ms 超时（上位机不知道线断了） |
| 底盘收到了但没执行 | 上位机 ACK 超时 |

**开机等待是上下位机的约定**：下位机 10 s 静默 + 4.2 s 自检 = 14.2 s 才接受指令，
所以上位机的 `BOOT_SILENCE_SEC` 必须是 15 s。写 10 s 的话，后面 4.2 s 的指令会被丢掉，
而上位机的 ACK 逻辑会把它误判成"指令没生效"。

### 电压滞回

停机阈值如果只判 `< 20.0`，就是个裸门限。

后果：电量卡在 20 V 附近时状态机会在 `RUN`/`IDLE` 之间反复跳，而每次离开 `RUN`
都会作废旧指令——表现是车一窜一停，操作员得反复重发。

本工程给停机阈值也加了滞回：

| 电压 | 判定 |
|---|---|
| < 20.0 V | 判欠压，**锁住** |
| 20.0 ~ 21.0 V（已锁住时） | 仍然不放行 |
| > 21.0 V | 解除锁存 |
| 20.0 ~ 21.0 V（未锁住时） | 正常可用 |

也就是说：启动门槛是 20 V，但一次欠压之后要回到 21 V 以上才能再动。上电时电压
正好在 20~21 之间仍可正常启动，滞回只防"刚停又想跑"。

### 故障显示

出 CoreFault、栈溢出、内存耗尽时，不再 `for(;;)` 静默挂着。

`fault_halt(tag)` 在异常上下文里直接：

1. 点红灯、蜂鸣器常响
2. 屏上写 `FAULT <tag>` + `CFSR` / `HFSR` / 出错地址（`MMFAR` 或 `BFAR`，取有效那个）
3. 然后停住

只用 GPIO 翻转和 SPI 写屏，不碰中断和调度器，异常上下文里是安全的。

| tag | 来源 |
|---|---|
| `HARD` | HardFault |
| `MMU` | MemManage |
| `BUS` | BusFault |
| `USAGE` | UsageFault |
| `NMI` | NMI |
| `STK` | 任务栈溢出 |
| `MEM` | 堆耗尽 |

开了看门狗的话，停 2 秒会被复位，那一屏就是唯一的现场记录。所以**上机时如果看到
屏上停在 FAULT，先把 `CFSR`/`HFSR` 抄下来再断电**。

### 中断优先级的取值

`configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY = 5`。串口和 CAN 的中断统一取 **5**。

取比 5 更高的优先级也能跑，因为这两个 ISR 都不调用 FreeRTOS API，只往环形缓冲里塞字节、
写全局变量。但那是个陷阱：哪天有人在 ISR 里加一句 `xQueueSendFromISR`，高于 5 的
优先级会直接破坏内核数据结构。

改成 5 之后，它们在法律意义上"允许"调用 FromISR 接口（虽然现在还不用），代价是慢了
两个优先级，而 0~4 全是空的，实际没有影响。

### 滤波器的自增长窗口

`meanf_push()` 在窗口没填满时按**已填个数**求平均，而不是拿全 0 的缓冲去平均。

这是为了消掉一类错误：第一版 `meanf_init()` 在初始化函数里漏调了，结果电压在开机后
前 32 拍（320 ms）是从 0 V 爬上来的，上位机会看到"电池 0.7 V"。现在即使调用方忘了
初始化也不会出现爬坡，测试里专门有一条"不调 init 也不能从 0 爬"。

### 控制环的时间基准

轮速是用"这一拍的编码器计数 ÷ 固定周期"算出来的。**只要这一拍的实际间隔不是
10 ms，速度就是错的**——而写 Flash 那 250 ms 关中断，正好制造这种间隔。

所以 `chassis_task` 每拍量一次真实间隔：

| 实际间隔 | 处理 |
|---|---|
| 正常 10 ms | 正常跑 |
| 超过 30 ms | 认为卡过。清编码器计数、清 PI、停电机，这一拍丢掉重来 |

丢掉一拍比喂一个放大 25 倍的速度安全得多：后者会让 PI 反向打满一个周期，车会抽一下。
状态机的 `dt_ms` 也用实测值，不用常量。

### CAN 的离线恢复

`NART` 开着（不自动重传）+ `ABOM` **也开着**（自动离线恢复）。

NART 是为了"总线上少一个节点时不要卡在发送里"。但只有 NART 不够：没人应答时每帧都
算错，TEC 涨到 255 就进 bus-off，而 ABOM 关着的话会**一直停在那儿直到复位**。超声波板
上电晚一点、插拔一下总线，都能触发。

ABOM 打开后，硬件在总线恢复后自己回来，不用复位。

### 参数可以在线调

`kp` / `ki` / 平滑步进 / 遥控速度基准都放在 `g_tune` 里，APP 发调参帧改，
`chassis_task` 每拍读一次（`pi_set_gains` + `g_tune.step_mm`），下一个周期就生效。

这些值全是 `uint16_t`，因为写的是 UART4 中断、读的是 100 Hz 任务，
浮点的读写在 Cortex-M4 上不是原子的，32 位整数是。

改完发 `W` 就写进 Flash（`params_save`，只在停车时执行），掉电后还在。

### 刀片的两套命令语义

刀片有两个入口，语义不同，不能混：

| 入口 | 刷新方式 | 判定 | 为什么 |
|---|---|---|---|
| 上位机 `CMD=6` | 会持续刷新 | 300 ms 内不刷新就关 | 上位机有定时器，能刷 |
| APP 按键 `W/V/P` | 一次性字节 | 开关式，保持到收到关命令 | 蓝牙 APP 没法刷新 |

两条都受 `allowed` 约束：失能、急停、欠压、自检期间一律强制关，并且把"意愿"一起清掉，
恢复允许后不会自己再开。

**已知风险**：APP 那条路是开关式，蓝牙断线时固件发现不了，刀片会继续转。
物理急停开关是唯一兜底。这是拿可用性换安全的取舍，写在 `DISCLAIMER.md` 里了。


否则蓝牙 APP 连不上。

### 声光指示

| 状态 | 灯 | 蜂鸣 |
|---|---|---|
| `INIT` | 白 | — |
| `IDLE` | 绿 | 自检通过回待命时两声短鸣 |
| `RUN` | 青 | — |
| `SELFTEST` | 黄闪 | 进自检一声 |
| `ESTOP` | 紫闪 | 进急停一声 |
| `FAULT` | 红 | 三声短鸣，之后每 3 秒再响一声 |

**灯用普通 GPIO 开关，不走 PWM。** 绿灯和舵机在同一个定时器上（`TIM9_CH1`/`CH2`），
共用 ARR/PSC，给灯做 PWM 会把舵机的 50 Hz 一起改掉。状态指示用纯色开关就够，
七种颜色都是现成的。

极性写成宏（`LED_ACTIVE_LOW`、`BUZZER_ON_LEVEL`），默认低电平点亮。
实机对不上就改这一个数字，不用动逻辑。

驱动由 `hmi_task` 每 100 ms 调一次，不需要专门开任务。

### 看门狗

喂狗点放在**空闲任务钩子**里，不是控制环里。控制环自己卡死时空闲任务一定跑不到，
正好是最需要复位的情况；反过来喂在控制环里，控制环卡着还在喂，狗就白装了。

只靠空闲钩子还漏一类：某个任务卡死、其他任务照常跑。所以加了一层心跳监督：

| 任务 | 位 |
|---|---|
| `chassis_task` | `WD_BIT_CHASSIS` |
| `telemetry_task` | `WD_BIT_TELEMETRY` |
| `imu_task` | `WD_BIT_IMU` |
| `hmi_task` | `WD_BIT_HMI` |

每个任务在主循环里，把自己那一位打上标记，空闲钩子里检查，**该标记的都标记过才喂狗**，喂完清位。
任何一个任务停了，位凑不齐，2 秒后复位。

**默认关闭（`USE_IWDG 0`）。** IWDG 一旦启动就停不下来，只有复位才能关；
超时值不经确认就打开，板子会反复重启而且救不回来。上机确认正常再改 1。

要注意的口子：参数保存那段是 250 ms 关中断，期间没有任何任务跑、也没有空闲钩子，
所以那 250 ms 是**直接吃掉看门狗预算**的。2 秒超时下还剩 1.75 秒。

### 驻车释放

判定在 `app/park.c`（纯函数，可测）。**四条安全前提缺一不可**：

| 前提 | 不满足时 |
|---|---|
| `imu_ok` | 不释放。宁可有电流声，也不要溜车 |
| `|ax|`、`|ay|` < 0.1 g 且 `az` > 0.9 g | 不释放（斜坡、倒扣） |
| 目标速度为 0 | 不释放 |
| 轮速 < 0.02 m/s | 不算静止，重新计时 |

释放期间**不驱动电机也不跑 PI**，积分不会重新积累。
PI 一直在跑，清掉还会涨回来；这里把源头掐掉了。

### 舵机平滑

每拍最多动 **40 µs**。自检扫描本身是 20 µs 一拍，不会被拖慢；协议下发那条路则从
"一步跳 1000 µs"变成 25 拍走完，舵机和齿轮都舒服些。



### 参数掉电保存

参数区在 **sector 3，0x0800C000，16 KB**。

选 16 KB 的扇区而不是最后那个 128 KB 的，理由只有一个：**擦除时间和扇区大小成正比**。
16 KB 约 250 ms，128 KB 要 1~2 秒。擦写期间 Flash 被占用，而中断向量表也在 Flash 里，
所以整段擦写必须关中断——这段时间越长，串口丢数据、控制环停摆的风险越大。

代码现在 26.5 KB（Code+RO 27164 字节），离 0x0800C000 还有 **21.5 KB** 余量。**代码涨过 48 KB 就要把参数区挪走**，
同时改 `bsp/flash.h` 里的地址和扇区号。

保存的时机：APP 发 `{W:1}` 只挂一个标志，真正擦写由 `hmi_task` 在
**状态是 IDLE** 时才做。车在跑的时候不做，那 250 ms 里没有任何中断。

校验三件事：magic、版本号、CRC32。即使 CRC 对上，数值荒唐（kp=0、步进=0、
避障距离越界）也一样拒收——宁可回默认值，也不要用一个能让车失控的参数跑。

**不做自动保存。** 每次改参数都写一次的话，Flash 寿命（1 万次）会被调试消耗。

### 避障

超声波板  通过 CAN 发两帧：`0x101` 是 A~D，`0x102` 是 E~F，单位 mm。
`link.c` 收下来存进 `g_state.dist_mm`，并维护一个新鲜度计数——500 ms 没有新帧就认为
超声波离线，避障直接放行，不会因为没模块就卡在那儿不动。

避障判定在 `avoid.c`，纯函数：

| 情况 | 行为 |
|---|---|
| 关着，或数据不新鲜 | 原样放行 |
| 六路全是 0（没模块） | 原样放行 |
| 有读数小于触发距离 | 连续 5 拍确认后才动作 |
| 确认后且在前述 | 哪边近就往反方向转，vx 置 0 |
| 确认后但在后退 | 不动。倒车时不去抢方向 |

**传感器编号的左右归属是假设**（A、B 一组，C、D 一组）。实车装反了把
`AVOID_AB_IS_RIGHT` 改成 0。

### I2C 是共享资源

**现在 I2C 上只有 ICM20948 一个设备。** OLED 是四线 SPI（PD7/PD6/PD5/PD4），不走这条总线。

互斥量保留着：现在只有 `imu_task` 用 I2C，确实没有竞争对手，但将来再挂设备就不用重新想
这件事。代价是每次事务多几次函数调用，可以忽略。

历史上这里是两个任务共用的：

| 任务 | 优先级 | 用途 | 一次事务耗时 |
|---|---|---|---|
| `imu_task` | 3 | 读 12 字节 | 约 0.5 ms |
| `hmi_task` | 1 | 刷一屏/一行 | 整屏 37 ms，一行 9 ms |

软件 I2C 是逐位翻转引脚的，**不可重入**：一个任务翻到一半被抢占，另一个任务发出 START，
两条传输都会报废。现象是 OLED 偶尔花屏、IMU 偶尔读到怪值，而且随机、难复现。

所以：**所有 I2C 事务必须用 `i2c_lock()` / `i2c_unlock()` 包起来**，粒度是整段事务而不是单个字节
（否则页地址会被别人改掉）。锁是 FreeRTOS 互斥量，需要 `configUSE_MUTEXES = 1`。

另外 hmi 改成每次只刷一行（2 页，约 9 ms）而不是整屏，把持锁时间从 37 ms 压到 9 ms，
免得 imu 任务被饿太久。整屏四行轮转一遍 400 ms。

## 三、中断

- 中断里只搬数据：入环形缓冲、置标志。**不做解析、不算浮点、不调 printf。**
- 需要调 FreeRTOS API 的中断，抢占优先级必须 ≥ 5（`configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY`）。
- 外设中断放在对应 bsp 模块里；`app/irq.c` 只放内核异常和 SysTick。

## 四、安全设计

### 状态机

```
INIT ──自检通过──> IDLE ──收到速度指令──> RUN
  │                 ↑                    │
  └──自检失败──> FAULT                  │失能条件成立
                  ↑                      ↓
                  └──────────────── ESTOP（锁存）
```

五个旧标志（`FlagStop` / `DeepCheck` / `phase` / `emergency_stop` / `selftest_trigger`）
合并成一个 `chassis_state_t`，避免"哪个标志说了算"的问题。

### fail-safe / fail-dangerous 判定

**改动按"出错时朝哪边失效"分类，默认值不同：**

| 改动 | 失效方向 | 默认 |
|---|---|---|
| 刀片命令超时关断 | 安全侧（最坏刀片不转） | 开 |
| 指令丢失停车 | 安全侧（最坏不动） | 开 |
| 急停锁存 + CMD=8 解除 | 安全侧 | 开 |
| 遥测 CAN ID 迁到 0x2xx | 无影响 | 开 |
| **IWDG** | **危险侧（喂错就反复复位）** | **关**，`USE_IWDG 0` |

理由：没有实机时，"失效即停"的可以默认开，"失效即复位/失效即动"的必须默认关。

### 阈值

集中在一处定义，不散落在各函数里：

| 项 | 值 | 位置 |
|---|---|---|
| 低压停车 | 20.0 V | `app/chassis_safety.c` |
| 指令丢失超时 | 500 ms | 同上 |
| 刀片命令刷新超时 | 300 ms | `app/blade.c` |
| 上电静默期 | 10 s | `app/chassis.c` |
| 超声波避障距离 | 0.5 m | `app/avoidance.c`（未实现） |

状态与转移条件见 [规格-底盘状态机.md](规格-底盘状态机.md)。

## 五、编码与命名

- 源文件 GBK，文档和 `.ps1` 用 UTF-8
- 类型用 `stdint.h` 的 `uint8_t` / `int16_t`，不用 `u8` / `u16`
- 文件、函数、变量小写下划线：`chassis_safety.c`、`safety_allow()`、`blade_cmd_deadline`
- 宏全大写：`PRIO_CHASSIS`、`CAN_ID_ULTRA_ABCD`
- 每个模块一对 `.c/.h`，头文件只暴露必要的接口，内部函数加 `static`



## 六、验证策略

验证分三层，第四层只能上机做：

| 层 | 手段 | 能证明什么 |
|---|---|---|
| 1 | Keil 编译（`UV4 -b`），0 error 0 warning | 类型、符号、链接、尺寸可控 |
| 2 | 纯逻辑模块不依赖硬件头，可单独编译 | 逻辑错误在编译阶段就暴露 |
| 3 | 上机（见 [上机清单.md](上机清单.md)） | 硬件相关的一切 |

第 2、3 层只对**不碰硬件的模块**有效。所以模块划分时，"能不能在 PC 上测"是一个设计约束，
不是一个事后补救。
