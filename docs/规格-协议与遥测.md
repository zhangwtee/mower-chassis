# 规格：协议与遥测

> 这份是协议，不含实现。改代码前先看这里，改完这里再改代码。
> 配套协议在 [mower-host](../../mower-host) 的 `bridge/mower_bridge/protocol.py`；
> 本文档描述的是**下位机应当呈现的行为**，以及模块之间的边界。

---

## 一、下行帧解析（`app/protocol.c`）

### 输入 / 输出

| 项 | 说明 |
|---|---|
| 输入 | 串口字节流，逐字节进来 |
| 输出 | 通过 sink 回调交出的**语义事件**，不是原始字节 |
| 依赖 | 无。只用 `stdint.h`，不 include 任何硬件头，不认识 `robot_control` / `charger` |
| 线程 | `protocol_feed_isr()` 只在接收中断里调；`protocol_poll()` 只在任务里调 |

### 阶段划分

| 阶段 | 在哪 | 做什么 | 不许做什么 |
|---|---|---|---|
| 入队 | 中断 | 把字节写进单生产者单消费者环形缓冲 | 解析、浮点运算、printf |
| 解析 | 任务 | 组帧、校验、分发 | 阻塞、动态分配 |

环形缓冲 256 字节，`head == tail` 表示空，实际容量 255。满了**丢新字节并累加 `overflow`**，不覆盖旧数据。

### 帧格式

```
偏移   0      1      2      3..8       9                  10
       0x7B   CMD    0x00   Data[6]    BCC = XOR([0..8])  0x7D
```

- BCC 固定覆盖 **9 字节**（含帧头、不含帧尾、不含 BCC 自身）
- `[2]` 不使用，不读

### 命令字与行为

| CMD | 事件 | 字段解释 | 边界处理 |
|:---:|---|---|---|
| 0 | `on_velocity(vx,vy,vz,src)` | `[3:4]/[5:6]/[7:8]` 为 int16 大端 mm/s | 无 |
| 1 | `on_recharge(vx,vy,vz,nav=1,src)` | 同上 | 无 |
| 2 | `on_recharge(vx,vy,vz,nav=0,src)` | 同上 | 无 |
| 3 | `on_dock(vx,vy,vz)` | 同上 | 无 |
| 4 | `on_servo(us)` | `[3:4]` int16 大端 µs | **限幅到 500~2500**，负数和越界都限幅|
| 5 | `on_selftest()` | 无字段 | 无 |
| 6 | `on_blade(on)` | **只看 `[3]` 单字节**，非 0 即开 | 上位机不发此命令 |
| 7 | `on_estop()` | 无字段 | 上层负责锁存 |
| 8 | `on_estop_release()` | 无字段 | 上层负责解锁存 |
| 其它 | 无，仅 `unknown_cmd++` | — | 不派发、不中断 |

单位换算：`mm/s → m/s` 在解析层完成（`值 / 1000.0f`）。

### 异常处理

| 情况 | 行为 |
|---|---|
| 帧外收到非帧头字节 | 丢弃，继续找帧头 |
| 帧尾不是 `0x7D` | `bad_frame++`，进入重同步 |
| BCC 不匹配 | `bad_frame++`，进入重同步 |
| 重同步 | 在已收的 11 字节里从第 2 个字节起找 `0x7B`；找到则把它之后的内容前移并继续组帧，找不到则清零状态 |

重同步的意义：一次误码不该连带丢掉后面那一帧。最开始的做法是直接把计数清零，等于丢一帧。

### 已知取舍

- `mm/s → m/s` 用 `/1000.0f`，与原来的的"整数商 + 余数×0.001"在最后一位可能有亚 ULP 差异。它只影响速度设定值，不影响协议字节。
- 环形缓冲不做溢出回压，靠 `overflow` 计数让问题暴露。

## 二、上行遥测（`app/telemetry.c`）

### 输入 / 输出

| 项 | 说明 |
|---|---|
| 输入 | **已经换算好的**整数值（mm/s、原始 ADC 值、mV） |
| 输出 | 写进调用方给的缓冲区 |
| 依赖 | 无 |
| 换算 | **本模块不做单位换算**，只按位摆放 |

这条边界是刻意的：帧格式是硬性约定，出错代价最高；把"换算"和"摆放"分开，摆放部分可以完全用常量对拍。

### 24 字节底盘帧

| 偏移 | 内容 | 类型 |
|---|---|---|
| 0 | `0x7B` | — |
| 1 | FlagStop | uint8 |
| 2..7 | Vx, Vy, Vz（mm/s） | 3 × int16 大端 |
| 8..13 | 加速度原始值 | 3 × int16 大端 |
| 14..19 | 陀螺仪原始值 | 3 × int16 大端 |
| 20..21 | 电池电压（mV） | uint16 大端 |
| 22 | BCC = XOR([0..21]) | uint8 |
| 23 | `0x7D` | — |

### 19 字节超声波帧

| 偏移 | 内容 | 类型 |
|---|---|---|
| 0 | `0xFA` | — |
| 1..16 | A~H 八路距离（mm） | 8 × int16 大端 |
| 17 | BCC = XOR([0..16]) | uint8 |
| 18 | `0xFC` | — |

未接的槽位填 0。模块只有 6 路，G/H 恒 0。

### 已知取舍

- BCC 长度有两个值（22 和 17），是这份协议最容易错的地方。用错不会崩，只会**永久丢包**。
- 尺寸：两个模块链接后约 600 字节（`Code`）。
