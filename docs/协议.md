# 协议

上位机那一侧的实现在 [mower-host](../../mower-host) 仓库的 `bridge/mower_bridge/protocol.py`，含收帧解析。

本文档只记录**下位机的实现约定**和**CAN 总线的 ID 分配**——后者是下位机独有的，上位机没有。

改协议时两边必须一起改，并且要跑上位机的 `bridge/test/test_protocol.py`。

---

## 一、串口：UART3，115200 8N1

### 下行（上位机 → 固件）：11 字节定长

```
[0]      [1]    [2]   [3..8]      [9]              [10]
0x7B     CMD    0x00  Data[6]     BCC = XOR([0..8]) 0x7D
```

**BCC 算 9 字节**（头算、尾不算、BCC 自己不算）。抄成 11 会永久丢包。

| CMD | 含义 | 固件行为 |
|:---:|---|---|
| 0 | 速度 | `[3:4]`→Vx、`[5:6]`→Vy、`[7:8]`→Vz，int16 大端，mm/s |
| 1 / 2 | 自动回充 | 走 `charger.Up_Move*`，置允许回充 |
| 3 | 红外对接 | 走 `charger.Dock_Move*` |
| 4 | 舵机 | `[3:4]` 脉宽 µs，**固件侧夹到 500~2500** |
| 5 | 自检 | 触发整机自检 |
| 6 | 刀片 | **上位机不发送**；固件保留分支（APP 蓝牙键是唯一入口） |
| 7 | 急停 | 清三轴速度、关刀片、置固件侧锁存 |
| 8 | 解除急停 | 清固件侧锁存（上位机已在发，此前固件无分支） |

`[2]` 恒 0，固件不读。

### 上行（固件 → 上位机）：24 字节定长 @ 20 Hz

```
[0]   [1]       [2:3] [4:5] [6:7]  [8:13]  [14:19]  [20:21]  [22]            [23]
0x7B  FlagStop  Vx    Vy    Vz     Acc     Gyro     Voltage  BCC=XOR([0..21]) 0x7D
```

**BCC 算 22 字节。** 除 `[1]`（uint8）外全是 int16 大端，电压是 uint16。

换算：速度 ÷1000 → m/s；加速度 ÷1671.84 → m/s²；角速度 ×0.00026644 → rad/s；电压 ÷1000 → V。

### 一个周期不止 24 字节

固件每周期发：24 字节底盘帧 + 19 字节超声波帧。后者帧头 `0xFA`、帧尾 `0xFC`，槽位顺序 A~H 各 int16（mm），`[17]` 是 BCC、`[18]` 是帧尾。

超声波未接入时 A~F 全 0，G/H 恒 0（模块只有 6 路）。

上位机的解析用"扫 `0x7B` → 取 24 字节 → 校验帧尾 + BCC → 失败丢 1 字节重扫"，所以这段追加帧不会导致失步。

### 上电静默 10 秒 + 自检 4.2 秒

`CONTROL_DELAY = 1000`，在 100 Hz 任务里自增 → 上电后 10 秒内丢弃所有下行帧。没有 NAK、没有回读，表现为"推杆不动，等一会儿就好"。

这个窗口同时是陀螺零偏的采样窗口，不能随意缩短。

## 一之二、UART4：蓝牙 APP（9600 8N1）

不是帧协议，是**裸的单字节按键**，没有帧头、没有校验。所以固件只认白名单：

| 字节 | 键 | 行为 |
|---|---|---|
| `0x57` | W | 刀片开（**开关式**，不要求刷新） |
| `0x56` | V | 刀片关 |
| `0x50` | P | 刀片关 |
| `0x53` | S | 触发自检 |
| `0x41`~`0x48` | A~H | 八方向摇杆,按住期间 APP 接管速度 |
| `0x40` / `0x00` | — | 摇杆松开 |
| `0x58` / `0x59` | X / Y | 速度基准 ±100 mm/s |

**蓝牙模块状态串会被过滤掉。** 模块连上/断开时吐 `+CONNECTING<<MAC`、`+CONNECTED`、
`+DISC:SUCCESS`、`+READY`、`+PAIRABLE`。不去掉的话 `+DISC:SUCCESS` 里的 `S`
会被当成自检键——蓝牙一断线就误触发自检。固件见到 `+` 就把整行吞掉。

### 调参帧

```
{<cmd>:<数字>}                  单参数
{#<n1>:<n2>:...:<n9>}           批量
```

| cmd | 参数 | 范围 |
|:---:|---|---|
| `0` | 遥控速度基准 mm/s | 0~3500 |
| `1` | kp | 1~10000 |
| `2` | ki | 1~10000 |
| `3` | 速度平滑步进 mm/s 每拍 | 1~200 |
| `8` | 纠偏系数 | 0~100 |
| `W` | 把当前参数写进 Flash（只在停车时执行） | — |

批量帧按顺序套用,第 9 个是纠偏系数。所有值都会被夹到上表的范围内，
格式对不上就整帧丢弃。

对不上的话就是没反应（帧被丢掉），不会把参数写成怪值。

### 字符串软复位

收到连续的 `reset` 五个字节会执行 `NVIC_SystemReset()`，给无线烧录用。

其它字节一律丢弃。蓝牙链路上的一次误码不应该变成刀片动作。



刀片在 APP 这条路上是开关式，意味着**蓝牙断线不会让刀片停**——固件发现不了。
物理急停开关是唯一的兜底，见 [DISCLAIMER.md](../DISCLAIMER.md)。

## 二、CAN1，1 Mbps

**同一条总线上有多个设备，ID 必须集中登记，不要在代码各处写裸数字。**

| 标准帧 ID | 方向 | 内容 | 谁发的 |
|---|---|---|---|
| `0x101` | 收 | 超声波 A/B/C/D，各 int16 大端，mm |超声波板|
| `0x102` | 收 | 超声波 E/F + 后 4 字节 0 | 超声波板|
| `0x105` | 发 | 对接速度 + 红外刷新时间 | 本固件 |
| `0x181` | 收 | 三轴目标速度，mm/s | 上游控制器 |
| `0x182` | 收 | 红外四路 + 充电状态 + 电流 | 回充板 |
| `0x201` | 发 | 底盘遥测 1/3：`[0x7B, FlagStop, Vx, Vy, Vz]` | 本固件 |
| `0x202` | 发 | 底盘遥测 2/3：`[AccX, AccY, AccZ]` | 本固件 |
| `0x203` | 发 | 底盘遥测 3/3：`[GyroZ, 电压, BCC, 0x7D]` | 本固件 |

扩展帧 `0x12345678`：回充板特征码探测，在板则回同样内容。

**为什么遥测不用 0x101/0x102**：那两个是超声波板的，同 ID 同总线会让任何第三方监听分不清收到的是距离还是速度。所以速度遥测挪到了 0x20~0x22。

ID 的唯一定义处是 `bsp/can.h`。
